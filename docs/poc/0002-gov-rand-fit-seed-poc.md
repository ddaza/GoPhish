# POC-0002 — Live-seed test: `gov-<rand>.fit` permutation fuzzing

Status: **complete** (round 1 executed; findings recorded)
Seed: `hawaii.gov-sdas.fit` (reported scam domain; defanged when reported to us
as `hawaii[.]gov-sdas[.]fit`)
Depends on: POC-0001 (toolchain probes, alterx DSL findings, guardrails)

This POC executes POC-0001 §3.1 stages 1–4 against a **real reported scam
domain** for the first time, with the fuzz scope deliberately narrowed to a
single hypothesis (§1). No production Go code changes.

---

## 1. Hypothesis and scope (fixed for this test)

The reported URL is `hawaii.gov-sdas.fit`:

```text
hawaii . gov-sdas . fit
└─┬─┘   └───┬───┘  └┬┘
subdomain  registrable  TLD
           domain
```

The deception lives in the **subdomain**: a naive user reads `hawaii.gov` and
stops reading. The scammer controls only the registrable domain
`gov-sdas.fit` and mints arbitrary subdomains under it (`hawaii.`,
`alabama.`, …). The registrar was **Gname**, which allows **bulk
registration**.

**Campaign hypothesis (under test):** the operator bulk-registers a family of
`gov-<rand>.fit` domains, where `<rand>` is a short random-looking alpha token
(`sdas` in the seed) swapped per registration — i.e. the siblings of the seed
are permutations of the `gov-XXX.fit` shape, not other shapes or TLDs.

**Scope, explicitly fixed:** candidates are `gov-{{rand}}.fit` only. No
`{{rand}}-gov.fit`, no `gov{{rand}}.fit`, no other TLDs, no typosquats. Other
shapes were generated by the pattern file but are **out of scope for this
test** and their results are excluded from the findings below.

## 2. Method

Pipeline (POC-0001 §3.1), all evidence read-only OSINT (RDAP + CT only; no
candidate domain was ever contacted — POC-0001 §3.2):

```text
seed  hawaii.gov-sdas.fit
  │   alterx: pattern gov-{{rand}}.{{zz}} × payloads/rands.txt (35 tokens)
  │   → 35 candidates of shape gov-<rand>.fit
  ▼
RDAP  https://rdap.org/domain/<candidate>   (1 req/s, custom UA)
  │   200 = registered, 404 = unregistered
  ▼
CT    crt.sh query for the seed: no certificates logged
```

`<rand>` payload (`poc/payloads/rands.txt`, 35 tokens): all anagrams of the
observed token `sdas`, home-row keyboard walks (`asdf`, `fdsa`, `qwer`, …) —
a common shape for bulk-registered scam tokens — and random-looking 4-char
strings of the same consonant/vowel profile as `sdas`.

## 3. Findings

### 3.1 RDAP signal validation (POC-0001 open item §2.1)

| Case | Query | Result |
| ---- | ----- | ------ |
| Positive (seed) | `gov-sdas.fit` | HTTP **200**, full RDAP body |
| Negative | `gov-zzqjw7382.fit` (invented) | HTTP **404** |

The 200/404 registration primitive is **confirmed reliable for `.fit`** (via
rdap.org bootstrap → authoritative registry, one 302 hop). This was the core
unvalidated assumption of the whole pipeline; it now holds for this TLD.

### 3.2 Seed registration record (from `rdap_pos.json`)

| Field | Value |
| ----- | ----- |
| Registrar | **Gname.com Pte. Ltd.** (matches the report) |
| Registered | **2026-03-25T18:43:17Z** (~6 months old at query time) |
| Expires | 2027-03-25T18:43:17Z |
| Last changed | 2026-05-24T18:43:20Z |
| Nameservers | `a.share-dns.com`, `b.share-dns.net` (shared DNS service) |
| Status | `client transfer prohibited`, **`client hold`** |

`client hold` is a registrar-level hold — the domain no longer resolves and is
commonly the result of an abuse action by the registrar. Consistent with CT
finding below.

### 3.3 CT (crt.sh) — seed has no certificates

`crt.sh?q=%.gov-sdas.fit` → HTTP 200, **empty result set** (`ct_seed.json` =
`[]`). No TLS certificate was ever logged for the seed or any subdomain. Two
readings, both worth carrying into `internal/detect`:

- consistent with `client hold`: infrastructure may have been torn down (or
  never reached the HTTPS stage) before/after suspension;
- a scam domain with **no CT presence is not necessarily inactive** — CT
  absence must not lower a score to zero. (crt.sh was also intermittently
  502 — flaky, as POC-0001 predicted; retries needed.)

### 3.4 Fuzz yield — the central measurement

Of the 35 in-scope `gov-<rand>.fit` candidates:

| RDAP result | Count | Domains |
| ----------- | ----- | ------- |
| 200 registered | 1 | `gov-sdas.fit` — **the seed itself** |
| 404 unregistered | 34 | every other candidate |

**Novel-hit rate: 0/34.** None of the 34 generated permutations — including
every anagram of `sdas` — is registered. The campaign hypothesis as stated
("siblings are `gov-<rand>.fit` with permuted/keyboard-walk tokens") is **not
supported** for this token set.

Interpretation (feeds directly into Plan.md §4.8 mini loop and POC-0001 §3.3
Q2 "is compositional fuzzing worth the lookup budget"):

1. **Blind random-token guessing has ~zero yield**, exactly as expected when
   the token space is ~26⁴ and we sample 35. Permutation fuzzing cannot
   recover a *random* sibling token — it can only confirm tokens we already
   suspect from other evidence.
2. The productive pivots are therefore **infrastructure-based**, not
   lexical: same-registrar (Gname) bulk clustering, shared nameserver
   (`share-dns.*`) co-tenancy, CT wildcard searches per TLD, and — most
   importantly — **more seeds from the same campaign** (each new reported URL
   re-primes the fuzzer with a real token). One seed is not enough to
   characterize a regex.
3. alterx's role is confirmed as POC-0001 §4 concluded: a combinatorial
   engine for *candidate enumeration once you have lexical material*, not a
   discovery engine.

### 3.5 Measured rate-limit datapoint (for `internal/throttle`)

At 1 req/s against rdap.org, HTTP **403 began after ~98 requests** (the only
5 affected queries were out-of-scope shapes; all 35 in-scope queries
completed cleanly at 1/s). Takeaway for Plan.md §4.6 defaults: budget
rdap.org at well under ~90 req per ~100 s window per IP, with
backoff-and-requeue on 403. (The 5 exhausted-shape 403s were not retried —
out of scope for this test.)

### 3.6 Tooling finding — alterx payload name collision

`-pp 'tld=tlds.txt'` **silently fails to expand** in alterx v0.1.0 (output
contains only the first TLD); renaming the payload (e.g. `{{zz}}`) restores
the full cross-product. No error is emitted. If alterx output is ever parsed
programmatically, candidate-count sanity checks are mandatory (a wrong count
was exactly how this was caught: 105 ≠ 3 × 35 × 12 = 1260).

## 4. Verdict

- Pipeline mechanics **validated end-to-end on a real seed**: seed → alterx →
  RDAP 200/404 → evidence JSONL, with provenance and throttling.
- Campaign hypothesis **rejected for this token set**: no `gov-<rand>.fit`
  siblings found. The seed appears to be either a singleton, already
  suspended (`client hold`), or part of a family whose other tokens are not
  near-permutations of `sdas`.
- **Do not build** blind random-token enumeration into `internal/fuzz`.
  **Do build** the infra pivots (registrar/NS clustering, CT) and the
  seed-accumulation loop.

| `evidence_gov-rand.fit.jsonl` | Focused evidence: 35 records — 1×200 (the seed), 34×404 |

Both were produced by filtering the round-1 artifacts (all 35 in-scope queries
completed before rate limiting appeared, so no re-querying was needed):

```bash
grep '^gov-[a-z]*\.fit$' candidates.txt > candidates_gov-rand.fit.txt   # 35
jq -c 'select(.query | test("^gov-[a-z]+[.]fit$"))' \
  evidence_round1.jsonl > evidence_gov-rand.fit.jsonl                    # 35
```

## 6. Compliance note

Defensive use on a domain reported to us as a scam (AGENTS.md §7.1). All
evidence is read-only RDAP/CT queries against public data; no candidate or
seed domain was contacted, no host scanned, no paid service used; candidate
generation was for detection only and this document contains no lure content
(§7.3). The single registered domain found is the originally reported seed;
no third party is newly accused — any future low-confidence sibling would be
labeled "suspicious, unverified" (§7.6). Artifacts are minimal and
disposable (§7.5).
